Product overview

VibePrompt

An AI-powered prompt engineering workspace for coding agents.
Evidence-first review before agent execution
Current product direction

VibePrompt today is an evidence-driven adversarial project reviewer, built as a FastAPI + React app with provider failover and structured project state.

Its core value is not generic prompt storage; it is challenging weak assumptions, unrealistic scope, and contradictory requirements before an agent spends tokens.

Why it matters

The product narrows a fuzzy idea into a better engineering brief, making it easier for an LLM or coding agent to act with context, constraints, and measurable completion criteria.

Slide 2 — The problem

Vague requests generate weak agent outcomes.

“Build me an e-commerce application.”
What breaks
  • Unclear requirements produce low-quality implementation.
  • Project-specific context is missing, so the model improvises.
  • Technical constraints are underspecified.
  • Different agents interpret the same brief differently.
  • Teams waste time refining prompts instead of shipping.
Typical failure mode

An autonomous coding agent receives an underspecified ask and chooses assumptions about stack, data model, auth, hosting, and delivery. The result is often a plausible artifact that is misaligned with the actual goal.

VibePrompt’s value: surface the missing assumptions before token-heavy execution begins.

Slide 3 — The solution

Turn a vague idea into an actionable engineering brief.

Before

“Build an e-commerce application.”

  • Ambiguous business goal
  • No stack constraints
  • No testing criteria
  • No definition of done

After

Structured project brief with:

  • Project objective
  • Functional requirements
  • Technology stack
  • Architecture constraints
  • Database requirements
  • Implementation stages
  • Testing criteria
  • Definition of done

This is the product’s central transformation: better inputs generate better code outputs. The app compiles a reliable project specification from structured evidence, not just unstructured chat.

Important distinction

The inference model and the target coding agent are separate concerns. VibePrompt can review and refine what should be sent to an external model, while the actual coding execution still happens in the target agent environment.

Slide 8 — BYOK and universal model integration

Bring Your Own Key is a future-facing direction, not a present claim.

Current implementation reality

The repository already includes native provider adapters for Gemini, OpenRouter, and Groq, plus an OpenAI-compatible adapter layer. It also supports an offline heuristic fallback so local demos and tests still work without keys.

Important: BYOK is framed in the product direction as a planned capability, not something the repo claims is fully implemented today.

Target long-term model mix
  • OpenAI
  • Google Gemini
  • Anthropic Claude
  • OpenAI-compatible APIs
  • Groq
  • OpenRouter
  • DeepSeek
  • Ollama
  • Together AI
  • Fireworks AI
  • Mistral

The architecture is built around provider abstraction, adapter layers, custom base URLs, model selection, capability detection, and credential isolation — but the repo should be presented as a serious foundation rather than a fully mature universal provider platform.

Model provider stack Gemini → OpenRouter → Groq failover
Visible architecture

  • backend/app/orchestration/ — selective model invocation and provider selection
  • backend/app/grill/ — review policy, findings lifecycle, critic reconciliation
  • backend/app/projects/ — structured project state and project operations
  • backend/app/compilation/ — readiness gate and specification compiler
  • frontend/ — interactive project/review workflow
Slide 10 — Product workflow in the app

What users do today

Core loop
  • Create a project with objective and initial message.
  • Send project or product context into the review workflow.
  • Get findings such as unrealistic scope, missing constraints, or contradictions.
  • Resolve or reject issues with evidence-based status changes.
  • Check deterministic readiness before specification generation.
  • Export a final markdown or structured spec.
Quality gate

Readiness is not a generic “looks good” score. It is a deterministic gate that blocks critical or high-risk gaps and encourages evidence-based progression.

The project stores messages, findings, and risk status in SQLite — which is a solid MVP foundation for further productization.
